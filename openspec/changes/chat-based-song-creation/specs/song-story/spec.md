## ADDED Requirements

### Requirement: Поле истории песни
Система SHALL хранить у песни необязательное текстовое поле `story` (колонка `songs.story`, Text, nullable). Поле SHALL присутствовать в `SongRead`, `SongUpdate` и в TypeScript-типе `Song`. Максимальная длина — 10000 символов; при превышении PATCH SHALL вернуть 422.

#### Scenario: Сохранение истории
- **WHEN** клиент отправляет `PATCH /songs/{id}` с `{"story": "..."}`
- **THEN** история сохраняется, `updated_at` обновляется, ответ содержит `story`

#### Scenario: Очистка истории
- **WHEN** клиент отправляет `{"story": null}` или пустую строку
- **THEN** `story` становится null

#### Scenario: Слишком длинная история
- **WHEN** `story` длиннее 10000 символов
- **THEN** сервер возвращает 422, данные не меняются

#### Scenario: Существующая песня без истории
- **WHEN** песня создана до появления поля
- **THEN** `story` равно null, остальные функции песни работают как раньше

#### Scenario: Миграция при старте
- **WHEN** backend стартует на БД без колонки `story`
- **THEN** выполняется `ALTER TABLE songs ADD COLUMN IF NOT EXISTS story TEXT`, повторный старт безопасен

### Requirement: Панель истории
Интерфейс SHALL показывать компактный блок `StoryPanel` на экране песни.
- Если `story` пуст — блок раскрыт: поле ввода, кнопка микрофона, кнопка «Сохранить».
- Если `story` задан — показан текст (свёрнутый до нескольких строк) и кнопка «Изменить историю».
- «Изменить историю» переводит блок в режим редактирования с текущим текстом; «Сохранить» отправляет PATCH, «Отмена» возвращает прежний текст без запроса.

#### Scenario: Первая история
- **WHEN** пользователь открывает песню без истории
- **THEN** блок истории раскрыт с пустым полем и микрофоном

#### Scenario: Изменение истории
- **WHEN** пользователь нажимает «Изменить историю», правит текст и жмёт «Сохранить»
- **THEN** отправляется PATCH с `story`, блок возвращается в режим просмотра с новым текстом

#### Scenario: Отмена
- **WHEN** пользователь жмёт «Отмена»
- **THEN** изменения отбрасываются, запрос не отправляется

#### Scenario: Ошибка сохранения
- **WHEN** PATCH завершился ошибкой
- **THEN** показано сообщение об ошибке, введённый текст не теряется

### Requirement: Голосовой ввод
Хук `useSpeechInput` SHALL использовать Web Speech API (`SpeechRecognition` / `webkitSpeechRecognition`), язык `ru-RU`, `interimResults=true`, `continuous=true`. Он SHALL возвращать `supported`, `listening`, `transcript`, `error`, `start()`, `stop()`. Звук не передаётся на сервер. Распознанный текст SHALL дописываться в конец поля, а не заменять его. Повторное нажатие микрофона останавливает запись.

#### Scenario: Диктовка истории
- **WHEN** пользователь жмёт микрофон и говорит
- **THEN** кнопка показывает состояние записи, промежуточный текст появляется в поле, итоговый дописывается к существующему

#### Scenario: Остановка
- **WHEN** пользователь жмёт микрофон повторно или уходит с экрана
- **THEN** распознавание останавливается, поле остаётся редактируемым

#### Scenario: Браузер без поддержки
- **WHEN** Web Speech API недоступен
- **THEN** кнопка микрофона скрыта, доступен ручной ввод

#### Scenario: Отказ в доступе к микрофону
- **WHEN** пользователь запретил микрофон или возникла ошибка распознавания
- **THEN** показано понятное сообщение, ввод с клавиатуры продолжает работать

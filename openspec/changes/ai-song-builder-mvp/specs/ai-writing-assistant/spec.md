## Purpose

Предоставляет набор AI-функций соавторства (анализ идеи, действия над строкой, создание хуков/припевов, рекомендации по структуре и исполнению, финальный разбор, подготовку трека), где каждое предложение AI применяется только по решению пользователя.

## ADDED Requirements

### Requirement: Анализ идеи песни
Система SHALL анализировать идею песни (и уже написанный текст, если он есть) и возвращать рекомендации по теме, эмоции, жанру, BPM, энергии и структуре секций, не изменяя сохранённый текст песни автоматически.

#### Scenario: Анализ новой идеи
- **WHEN** пользователь запускает анализ песни, у которой заполнено поле `idea`
- **THEN** система возвращает тему, эмоцию, жанр, BPM, энергию и рекомендуемую структуру секций и сохраняет их в `analysis` песни

#### Scenario: Пользователь меняет результат анализа вручную
- **WHEN** пользователь изменяет любое поле анализа (например, жанр или BPM) после получения рекомендаций
- **THEN** система сохраняет изменённое пользователем значение и не перезаписывает его автоматически

### Requirement: Действия над строкой текста
Система SHALL предоставлять действия Variants, Continue, Rewrite, Rhyme, Flow и Vocal для выбранной строки или выделенной части строки, используя контекст песни (идею, жанр, BPM, эмоцию, уже написанный текст).

#### Scenario: Получение вариантов строки
- **WHEN** пользователь выбирает строку и запрашивает действие Variants
- **THEN** система возвращает несколько альтернативных вариантов этой строки, не изменяя сохранённый текст песни

#### Scenario: Продолжение текста
- **WHEN** пользователь запрашивает действие Continue от текущей позиции в тексте
- **THEN** система возвращает предложенное продолжение, учитывающее уже написанные строки

#### Scenario: Действие над выделенной частью строки
- **WHEN** пользователь выделяет часть строки и запрашивает Rewrite или Rhyme
- **THEN** система возвращает варианты, затрагивающие только выделенный фрагмент, сохраняя остальную часть строки без изменений

### Requirement: Create Hook и Create Chorus
Система SHALL генерировать варианты хука и припева с учётом контекста песни (темы, жанра, эмоции, уже написанного текста).

#### Scenario: Создание хука
- **WHEN** пользователь запрашивает Create Hook для песни с заданной темой и жанром
- **THEN** система возвращает несколько вариантов хука, согласованных с контекстом песни

#### Scenario: Создание припева
- **WHEN** пользователь запрашивает Create Chorus для песни с уже написанными куплетами
- **THEN** система возвращает варианты припева, учитывающие содержание и настроение куплетов

### Requirement: Рекомендации по структуре и исполнению
Система SHALL предоставлять предложения по структуре секций, flow и исполнению на основе текущего состояния песни, без автоматического применения изменений.

#### Scenario: Предложение структуры
- **WHEN** пользователь запрашивает рекомендации по структуре для песни с частично написанным текстом
- **THEN** система возвращает предложенную последовательность секций (например, `[VERSE]`, `[CHORUS]`), которую пользователь может принять или отклонить

### Requirement: Finish Song анализ
Система SHALL выполнять финальный анализ завершённой песни и возвращать рекомендации по улучшению, не изменяя текст песни автоматически.

#### Scenario: Запрос финального анализа
- **WHEN** пользователь запрашивает Finish Song для песни с заполненным текстом
- **THEN** система возвращает список замечаний и рекомендаций, а исходный текст песни остаётся неизменным до явного действия пользователя

### Requirement: Prepare Track
Система SHALL формировать данные для подготовки трека: Lyrics, Style Prompt, Negative Style, Performance-рекомендации и Generation Settings на основе содержимого и анализа песни.

#### Scenario: Подготовка данных трека
- **WHEN** пользователь запрашивает Prepare Track для песни с заполненным текстом и анализом
- **THEN** система возвращает Lyrics, Style Prompt, Negative Style, Performance-рекомендации и Generation Settings, сохраняя их в песне

### Requirement: Контекст песни в каждом AI-запросе
Каждая AI-функция SHALL автоматически собирать контекст песни (идею, жанр, BPM, эмоцию, уже написанный текст) и передавать его в запрос к AI-провайдеру, не требуя от пользователя повторного ввода этих данных.

#### Scenario: Автоматическая сборка контекста
- **WHEN** пользователь вызывает любое AI-действие (например, Continue) для существующей песни
- **THEN** система включает в запрос к AI-провайдеру текущие идею, жанр, BPM, эмоцию и уже написанный текст песни без дополнительного ввода от пользователя

### Requirement: Валидация и логирование AI-ответов
Система SHALL валидировать каждый ответ AI-провайдера по строгой схеме и сохранять каждый AI-запрос и ответ как отдельную запись в истории сообщений песни.

#### Scenario: Валидный ответ сохраняется в истории
- **WHEN** AI-провайдер возвращает ответ, соответствующий ожидаемой схеме
- **THEN** система сохраняет запрос и ответ как записи `messages`, связанные с песней

#### Scenario: Невалидный ответ не повреждает данные песни
- **WHEN** AI-провайдер возвращает ответ, не соответствующий ожидаемой схеме
- **THEN** система возвращает ошибку пользователю и не изменяет сохранённые данные песни

### Requirement: Единый AI-провайдер PolzaAi
Система SHALL использовать единый AI-сервис на базе PolzaAi (OpenAI-совместимый API) с моделью `claude-haiku-5.5` для всех AI-функций проекта.

#### Scenario: Использование общего провайдера
- **WHEN** выполняется любое из AI-действий (анализ идеи, действия над строкой, create hook/chorus, finish song, prepare track)
- **THEN** запрос отправляется через единый AI-сервис с моделью `claude-haiku-5.5`, настроенной через переменные окружения

#### Scenario: Недоступность провайдера
- **WHEN** PolzaAi недоступен или отвечает с ошибкой сети либо таймаутом
- **THEN** система возвращает понятную ошибку пользователю, не повреждая существующие данные песни

## ADDED Requirements

### Requirement: Экран песни из двух частей
Экран песни SHALL состоять из: компактного блока истории (`StoryPanel`), верхней части с текстом, созданным ИИ (только чтение), и нижней части с чатом (`SongChat`). `LyricsEditor`, `LineActionPanel`, `HookChorusPanel`, `FinishSongPanel`, `PrepareTrackPanel`, `LyricsDraftPanel` SHALL быть удалены вместе с их использованием и неиспользуемым кодом в `api/client.ts` и `types/index.ts`. Сохраняются заголовок песни, выбор пресета/темы и копирование/экспорт текста, если они уже есть и не перегружают экран.

#### Scenario: Открытие песни
- **WHEN** пользователь открывает песню
- **THEN** сверху виден текст по секциям, снизу — история чата, поле ввода, кнопка отправки и микрофон

#### Scenario: Пустая песня
- **WHEN** у песни нет `lyrics` и сообщений
- **THEN** сверху показана подсказка («Расскажите историю и напишите в чат, с чего начать»), чат пуст

#### Scenario: Загрузка истории сообщений
- **WHEN** экран открыт у песни с сообщениями
- **THEN** сообщения загружаются из `messages` по порядку `created_at`, чат прокручен вниз

### Requirement: Отображение текста
Верхняя часть SHALL разбирать `lyrics` по тегам секций `[Intro]`, `[Verse N]`, `[Pre-Chorus]`, `[Chorus]`, `[Bridge]`, `[Outro]` (регистр не важен) и показывать каждую секцию отдельным блоком с названием. Текст вне тегов показывается как секция без названия. Редактирование вручную недоступно; допустимо только копирование.

#### Scenario: Секции
- **WHEN** `lyrics` содержит `[Intro]`, `[Verse 1]`, `[Chorus]`, `[Bridge]`, `[Outro]`
- **THEN** показаны пять блоков в порядке появления, повторяющиеся секции (например два `[Chorus]`) показаны отдельно

#### Scenario: Обновление после ответа ИИ
- **WHEN** чат вернул новый `lyrics`
- **THEN** верхний текст перерисовывается без перезагрузки страницы, изменившиеся секции подсвечиваются

### Requirement: Эндпоинт чата
Система SHALL предоставлять `POST /songs/{id}/chat` с телом `{"message": str}` (1–4000 символов после trim). Эндпоинт SHALL в одной транзакции сохранить сообщение пользователя (`role="user"`), вызвать ИИ, сохранить ответ (`role="assistant"`) и обновить `songs.lyrics`. Ответ: `{"reply": str, "lyrics": str | null, "messages": [Message, Message]}`. Если ИИ не изменил текст, `lyrics` не перезаписывается.

#### Scenario: Успешное сообщение
- **WHEN** пользователь отправляет «усиль припев»
- **THEN** сохранены два сообщения, `lyrics` обновлён, клиент получил `reply` и новый `lyrics`

#### Scenario: Ответ без правки текста
- **WHEN** ИИ только задаёт уточняющий вопрос
- **THEN** сохранены оба сообщения, `lyrics` не меняется, в ответе `lyrics` равен текущему значению

#### Scenario: Песня не найдена
- **WHEN** `id` не существует
- **THEN** 404, сообщения не создаются

#### Scenario: Пустое сообщение
- **WHEN** `message` пуст или состоит из пробелов
- **THEN** 422, ничего не сохраняется

#### Scenario: Сбой провайдера ИИ
- **WHEN** провайдер вернул ошибку или невалидный ответ
- **THEN** сервер отвечает 502, `lyrics` не меняется, сообщение пользователя сохраняется, ассистентское — нет

### Requirement: Контекст ИИ
Запрос к ИИ SHALL включать: `story`, тему (`idea`), жанр и параметры пресета (название, жанр, BPM, energy, `style_prompt`, `negative_style_prompt`, `hooks_prompt`, `effects_prompt`, `chorus_vocal_style`), текущий `lyrics`, последние 20 сообщений чата и новое сообщение. Отсутствующие поля (null) SHALL пропускаться. Жанр SHALL использоваться как контекст, а не как жёсткое ограничение.

#### Scenario: Промпт содержит контекст
- **WHEN** формируется промпт чата
- **THEN** он содержит все заданные поля и последние сообщения в хронологическом порядке

#### Scenario: Песня без пресета и истории
- **WHEN** `preset_id` и `story` равны null
- **THEN** промпт строится из темы, текущего текста и сообщений, без пустых заголовков

### Requirement: Поведение ИИ
Системный промпт SHALL требовать: опираться на историю и тему; выстраивать структуру с тегами секций (intro, verse, pre-chorus, chorus, bridge, outro) и хуками; менять только затронутые просьбой секции и сохранять остальной текст дословно; возвращать краткий комментарий (`reply`) и полный обновлённый `lyrics`; при неясной просьбе задавать один уточняющий вопрос; отвечать на языке пользователя. Ответ провайдера SHALL разбираться как JSON `{"reply", "lyrics"}`; при невалидном JSON — одна повторная попытка, затем 502.

#### Scenario: Первый черновик
- **WHEN** `lyrics` пуст, а пользователь просит начать
- **THEN** ИИ создаёт структуру с тегами по истории и теме

#### Scenario: Точечная правка
- **WHEN** пользователь просит изменить только bridge
- **THEN** остальные секции в новом `lyrics` совпадают с прежними

### Requirement: Чат в интерфейсе
`SongChat` SHALL показывать сообщения пользователя и ИИ разными стилями, отправлять сообщение по Enter (Shift+Enter — перенос строки) и по кнопке, поддерживать диктовку через `useSpeechInput` (текст попадает в поле ввода и отправляется только по явному действию). Во время запроса поле и кнопка заблокированы, показан индикатор «ИИ пишет…». При ошибке сообщение остаётся в поле, показан повтор.

#### Scenario: Отправка текстом
- **WHEN** пользователь вводит сообщение и жмёт Enter
- **THEN** сообщение сразу появляется в чате, затем ответ ИИ, верхний текст обновляется

#### Scenario: Отправка голосом
- **WHEN** пользователь диктует просьбу и жмёт «Отправить»
- **THEN** распознанный текст отправляется как обычное сообщение

#### Scenario: Ошибка запроса
- **WHEN** запрос завершился ошибкой
- **THEN** показана ошибка, текст сообщения не потерян, можно отправить снова

### Requirement: Без лишних кнопок
Экран SHALL NOT содержать отдельных кнопок действий над строками, хуков, финализации и подготовки трека; все правки выполняются просьбами в чате.

#### Scenario: Проверка интерфейса
- **WHEN** пользователь открывает песню
- **THEN** действия доступны только через историю, чат, микрофон и копирование/экспорт

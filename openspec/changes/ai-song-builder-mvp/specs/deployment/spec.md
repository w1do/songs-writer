## Purpose

Определяет требования к запуску приложения через Docker Compose как набора из трёх сервисов (frontend, backend, postgres) с конфигурацией через переменные окружения и без хранения секретов в репозитории.

## ADDED Requirements

### Requirement: Три сервиса в Docker Compose
Система SHALL запускаться как набор из трёх сервисов Docker Compose: frontend, backend и postgres.

#### Scenario: Запуск всех сервисов
- **WHEN** выполняется команда `docker compose up -d --build`
- **THEN** поднимаются и становятся доступны сервисы frontend, backend и postgres

### Requirement: Персистентность данных PostgreSQL
Данные PostgreSQL SHALL сохраняться в Docker volume, переживающем пересоздание контейнеров.

#### Scenario: Перезапуск контейнеров без потери данных
- **WHEN** контейнер postgres пересоздаётся (например, после `docker compose down` и `docker compose up`)
- **THEN** ранее сохранённые записи `songs` и `messages` остаются доступны

### Requirement: Конфигурация через переменные окружения
Система SHALL получать `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `SESSION_SECRET`, ключ и имя модели AI-провайдера исключительно из переменных окружения.

#### Scenario: Запуск без обязательных переменных
- **WHEN** backend запускается без одной из обязательных переменных окружения (например, без ключа AI-провайдера)
- **THEN** система сообщает об ошибке конфигурации и не маскирует отсутствие значения значением по умолчанию с секретом

### Requirement: Отсутствие секретов в репозитории
Репозиторий SHALL содержать только файл `.env.example` с плейсхолдерами значений, без реальных секретов.

#### Scenario: Проверка репозитория на секреты
- **WHEN** просматривается содержимое репозитория
- **THEN** реальные значения `ADMIN_PASSWORD`, `SESSION_SECRET` и ключа AI-провайдера отсутствуют, присутствуют только плейсхолдеры в `.env.example`
